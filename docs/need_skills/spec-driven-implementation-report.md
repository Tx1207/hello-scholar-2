## Handoff 开发对照

实际模型为 `gpt-5.6-sol`，推理设置 high。一个独立编写的开发案例，每组两次；交接作者与续做者均为新 Agent，续做者只获得项目及交接，不获得原会话事实或私有检查。准备、交接封存和结果评价分阶段执行，四次作者阶段均通过原文件未变、仅新增交接的检查。

| 组别 | 仅写交接 | 续做产物通过独立检查 | 用户 README 保留 | 产物成对结论 |
| --- | --- | --- | --- | --- |
| 无 handoff 技能 | 2/2 | 2/2 | 2/2 | 对照同样成功 |
| 新版 handoff | 2/2 | 2/2 | 2/2 | 0 胜、2 平、0 负 |

私有检查验证 NFC、ASCII 空格/tab、非 ASCII 空白、大小写、CR/LF 拒绝及用户备注。每个续做项目均通过 4 个测试方法；另检查 README 全文和未生成 Plan/Tasks。没有以生成文档的标题数量或作者自评作为通过依据。

一项运行异常必须单列：`baseline-1` 留下实现和测试后，约十分钟没有返回完成状态，且没有回应协调者的状态询问；协调者暂停该 Agent 后才执行独立检查。该组产物和缓存原样保留，没有换一位 Agent 重做或剔除这次运行。其余三位续做者正常返回完成结果。比较器只评价上述产物检查，不判断 Agent 是否正常结束；因此表中的 2 个平局不是四次完全自主收尾的证明。这次异常的原因未确定，不能归因于有无技能。

结论：新版 handoff 在本案例中的产物可用，未观察到这些已检查行为的退步，但没有证明额外收益或稳定性改善。两组请求的工具预算相同；未独立计量 tokens、耗时或成本，不能宣称效率提高。
