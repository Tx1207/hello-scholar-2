# 面向 GPT-6 的技能审计与改进计划

日期：2026-09-06。历史实施前审计：旧技能路径、行号、建议和基线结果均指改造前状态，不作为当前待办。当前范围与进度统一见 [项目改进总览](spec-driven-skill-design.md)，实际结果见 [验收证据](quality-acceptance-status.md)。

后续已形成 [具体改进方案](spec-driven-skill-design.md)。本文保留审计事实和初步建议；实施细节以该方案为准，其中将新 schema 的范围收敛到 Record，并明确了 Spec 状态、安装升级和验收规则。

## 1. 结论与依据

建议取消 `writing-plans`、`generating-tasks` 及其强制审批链，让已确定的 Spec 直接约束实施和验收。与此同时，取消全局技能路由器，合并设计与 Spec 管理，保留项目特有的文档身份、科研证据和按需审计能力。

“不需要 Plan、Tasks skill”不等于“不需要思考实施顺序”，也不等于“Spec 接受后可以执行任何外部操作”。实施顺序交给当前 Agent 根据代码和风险调整；授权沿用用户已给出的目标、范围和停止条件。

本次完整阅读了 `AGENTS.md`、`AGENTS-zh.md` 和全部 16 个 `skills/*/SKILL.md`。同时检查了中文镜像的关键约束、技能调用元数据、部分模板与参考材料，以及安装器、文档校验与索引的相关实现和测试。没有逐字复审全部历史评估附件，也没有运行模型对照实验。

来源为用户提供的 Eric Provencher 文章 [Rethinking skills and prompts for GPT-6 Astra](https://x.com/pvncher/status/2095991462416490862)，本轮已读取正文。文章建议：

- 描述尽量短，只表达明确的适用场景，减少相互竞争的触发。
- 多分支技能使用简短入口，按任务需要读取参考文件。
- 重新检查固定步骤、全文件阅读和重复测试要求是否仍有收益。
- 明确已授权工作可以持续推进，避免多余审批使模型过早结束。
- 以结果和停止边界约束任务，并考虑不同模型的实际表现。

OpenAI 官方模型、提示和 Codex Skills 页面本轮返回 Forbidden 或 Cloudflare 拦截，未取得可引用正文。本文的 GPT-6 建议来自上述文章和本地审计，不宣称已经得到官方文档独立确认或 GPT-6 实测证明。

## 2. 优先处理的发现

### P1：执行被重复的文档与审批状态锁住

`skills/brainstorming/SKILL.md:32` 将共同理解、设计批准、Spec 分类、Spec 接受、Plan 批准、Tasks 批准和实施授权分开；末尾又把实施请求转给 `writing-plans`。`writing-plans` 要求固定 12 节 Plan 并交给 Tasks；`generating-tasks` 要求 2–5 分钟动作、七项固定字段及再次审核。

`skills/using-helloscholar/SKILL.md:54` 进一步把续做绑定到已批准 Tasks、文档修订和完整平台任务镜像。镜像不存在或同步失败就停工。即使 Spec 已经充分，用户仍需维护中间文档才能执行。

建议：移除 Plan/Tasks 作为执行前提。用户说“按此 Spec 实现”即授权范围内实施、相关验证和必要文档更新；仅要求设计时停在设计结果；重大未决产品选择或超出既有授权的操作才需要提问。

### P1：技能路由器过度触发，并声明了错误的指令优先级

`skills/using-helloscholar/SKILL.md:11` 要求只要 1% 可能适用就必须调用技能；其第 20 行声称 Skills 可以覆盖默认 system prompt。这既扩大了无关加载，也无法改变宿主的真实指令层级。

建议：删除该运行时 Skill，使用平台原生技能发现。AGENTS 只提供少量项目事实及明确的专用能力入口。平台工具适配移到安装文档，按真实可用工具执行。

### P1：删除目录不足以完成升级

`src/document-validation.js:242` 校验 Tasks 必须有 Plan；第 484 行要求 Record 的 `spec`、`spec_revision`、`plan_revision` 三者同时存在或同时为空；第 885 行要求关联 Record 有对应 Plan。`src/index-generator.js:105` 等位置把 Plan/Tasks 状态写入索引。

现状需要区分：缺少 Plan/Tasks 本身是 notice，不是 CLI error；真正阻止实施和审计的是 Skills 的生命周期门。只删技能仍会保留旧索引语义、Record 关联限制和其他技能的失效调用。

`src/install.js` 的安装和卸载都只遍历当前源目录发现的技能。退休技能被删后，旧 copy 安装不会因此消失；link 安装可能留下断链。`src/fs-ops.js` 的 `existsSync` 判断也会漏掉断链。

建议：文档模型、索引、Record 绑定和受管安装升级一起设计。对用户项目中的旧文档与修改过的技能副本先识别归属，不自动删除。

### P1：只读审计被要求先满足“全部完成”

`skills/converge-to-spec/SKILL.md:14` 要求 Tasks 已完成、全部勾选且各层审批均有效，才允许扫描实现。用户希望发现尚未完成的 Spec 项时反而无法进入审计。

建议：任意实施阶段均可对照指定 Spec 审计；逐项给出已满足、部分满足、未满足或证据不足。只读审计不修改代码；用户同时要求修复时，继续处理已授权范围内的缺口。

### P2：全局规则重复通用工程能力，却缺少本项目的操作事实

`AGENTS.md:9` 对每次修改强制全文阅读，`AGENTS.md:99` 对多阶段流程要求逐阶段注释。十个章节反复强调思考、范围、验证、完成和说明，对小改动也施加相同负担。

这些规则还通过 `src/install.js` 整份注入目标项目，意味着框架开发约定与被安装项目规则没有独立来源。本仓库的 `npm test` 不应因此变成所有使用者项目的测试命令。

建议：区分维护本仓库的 AGENTS 与安装到使用者项目的简短规则模板。分别放项目事实和协作契约，不复制整套通用编程教材。

### P2：专用能力被固定格式和重复确认稀释

`docs-maintenance` 即使收到 Architecture 更新请求，仍要求先输出零写入 Proposal、批准文件 Hash，再另轮写入。`takeoff` 与 `landing` 即使被同轮明确请求，也要求分轮调用，且规定大量固定标题和结尾提问。`test-driven-development` 有 398 行，并多次要求删除先写出的代码重来。`using-git-worktrees` 对 `.gitignore` 的必要小改动、环境准备失败和基线失败都设置额外停点。

建议：保留真实风险与事实约束；取消仅为遵循步骤而停工。Hash 用于检查并发变化，不能自动等同于重新审批。TDD 保留先失败再通过的行为证据，去掉惩罚性重写要求。无关基线失败应报告，不能伪装为通过，也不必一概阻断范围内独立工作。

### P2：测试与维护指导会把旧流程固化

`test/test_using_helloscholar_skill.py` 要求完整镜像、固定路由阶段和特定措辞。`test/skill_eval_contract.py:51` 的正式协议绑定 Terra、Sonnet、Haiku，不能据此推断 GPT-6 收益。

`writing-great-skills` 将“每次走同样的过程”作为首要目标，并把某个平台的调用元数据描述成通用行为。其 Codex YAML 实际使用 `allow_implicit_invocation: false`，正文却指导 `disable-model-invocation`；不能据此承诺所有平台都隐藏描述或实现零上下文成本。

建议：保留格式解析、文件归属、数据完整性等确定性测试；行为评估比较结果、干预次数和成本，允许有效的不同执行路径。历史结果保留原模型和协议，另建 GPT-6 对照组。

### P2：语言和平台参考已经出现漂移

AGENTS 明确支持当前任务的语言覆盖，但多份技能仍强调按仓库语言选模板，且不要根据任务提示决定语言；应统一为“本任务明确指定 > 目标文件或项目既有语言 > 项目默认”。

`skills/using-helloscholar/references/codex-tools.md` 仍引用已删除的技能，并把 detached HEAD 泛化成不能建分支、推送或 PR，后文甚至建议直接提交全部工作。应以真实工具能力和当前授权为准，不能由工具映射暗中扩大提交范围。

`manage-specs` 的 Successor 分支在创建新 draft 时就把旧 active Spec 标记为 superseded。建议将“候选替代关系”和“正式替代生效”分开，避免草案尚未采用时现有契约失去归属。

## 3. 全部技能的处置建议

下表是建议的目标目录，不代表已经删除。正文长短按内容负担判断，不能仅按行数判断；例如 `landing` 只有 61 行，却有约 7.8 KB。

| 当前 Skill | 建议 | 应保留的实际价值与修改边界 |
| --- | --- | --- |
| `writing-plans` | 删除 | 顺序与实现策略交给 Agent；有外部迁移约束时写入 Spec 的相关章节，不再生成独立审批 Plan。 |
| `generating-tasks` | 删除 | Agent 可用原生临时任务工具分解工作；取消 tasks.md、固定 TNNN、2–5 分钟动作和镜像协议。 |
| `using-helloscholar` | 删除 | 实验、续做等少量项目约定归入简短规则；原生发现负责选择技能。 |
| `brainstorming` | 合并到 `manage-specs` | 保留有价值的需求澄清和方案比较；已明确的需求不重复访谈，不强制固定数量方案。 |
| `manage-specs` | 保留并重写 | 单一入口负责设计和 Spec 身份；按创建、修订、替代读取参考；只在归属或行为有实质歧义时提问。 |
| `converge-to-spec` | 保留并重写 | 任意阶段核对 `Spec AC → 实现 → 证据`；移除 Plan/Tasks 门和 Convergence Tasks 写入分支。 |
| `record-experiment` | 核心保留，缩短入口 | 保留复现信息、运行身份、原始输出、失败和负结果；字段、远程执行与派生报告按分支读取。去掉 Plan 绑定。 |
| `docs-maintenance` | 核心保留，简化模式 | 保留 check/index/architecture/recover 的操作差异；已授权的关联维护可以连续执行，不再强制模式选择或 Hash 审批。 |
| `handoff` | 默认安装，保留 | 提供跨会话可恢复事实；引用 Spec、代码和 Record，记录当前未完成事项，不复制完整设计。 |
| `grilling` | 默认安装，保留 | 用户主动要求深入质询时逐个解决关键决定；取消无条件派遣子 Agent 和穷尽每个分支的要求。 |
| `crash-audit` | 默认安装，压缩 | 保留两项独特问题：最不确定之处、最大的遗漏；删重复触发词与多次重述的禁令。 |
| `takeoff` | 默认安装，压缩 | 保留重判目标和检验大胆假设的作用；删固定标题清单，允许完成用户同轮请求的后续分析。 |
| `landing` | 默认安装，压缩 | 保留可行性、代价、最大风险与停止条件；删除强制分轮与复杂标签，不默认链接其他 Skill。 |
| `test-driven-development` | 移出默认运行时技能目录 | 通用 TDD 交给模型；科研、Agent 评估的证据选择示例保留为维护参考。用户明确要求 TDD 时仍执行。 |
| `using-git-worktrees` | 移出默认运行时技能目录 | 通用 Git 操作交给宿主和 Agent；保留项目真实隔离约定及有价值的边界说明，移除工具名硬映射。 |
| `writing-great-skills` | 移为项目维护文档 | 将目标改为更可靠的结果与必要约束；保留渐进披露和去重原则，替换跨平台未经验证的元数据承诺。 |

目标为九个运行时技能，全部随默认安装提供。安装与调用分开：技能是否使用由当前请求和职责决定，不需要用户额外选择安装项。不为 GPT-6、其他模型各维护一整套复制的指令树。平台特有设置放对应适配文件，并实际检查是否生效。

## 4. Spec 驱动的目标契约

```text
用户目标与已有授权 + Spec
              ↓
主 Agent 理解代码、安排步骤、实施并验证
              ↓
验收条件与当前证据
       ↙              ↘
正式实验 Record     按需更新 Architecture / Handoff
```

日常小修复可直接执行，无需补写 Spec。需要持久设计时保留现有 `hello-scholar/specs/<topic>/SPEC-NNN-<name>/spec.md` 路径，避免没有收益的目录迁移。

Spec 保留目标、非目标、行为、接口、不变量、实施边界和验收标准。仅在涉及真实外部依赖时增加迁移、兼容及回滚要求。不要把已删除 Plan 的 12 节和 Tasks 的全部字段搬进 Spec。

验收项使用稳定标识，以便说明“哪个要求由什么证据证明”。没有命令证据的设计审计可以记录代码证据及其局限；完成实施时提供适合该变更的当前验证。Spec 的目标修订与执行证据更新应区分，补充验证结果不应让已接受设计自动失效。

执行状态采用最小方案：沿用 Spec 生命周期；在验收章节保存简短的完成证据与剩余缺口，不另建强制 execution.md 或新的任务审批文档。CLI 可以报告文档自报的状态，但不能只凭勾选就证明行为已实现。

同一会话压缩后继续使用可用上下文与工具状态；新会话从用户指定 Spec、当前代码和可信证据恢复。只有多个目标确实无法区分时才询问。需要长时交接时使用 Handoff，引用当前 Spec 修订并记录剩余工作；Handoff 不替代 Spec 的目标定义。

Spec 改变后重新核对受影响验收项和已有实现，不重建全部执行计划。保留仍有效的决策与证据，明确失效证据的原因。

## 5. AGENTS.md 的重写边界

建议区分两份各司其职的来源：仓库根 AGENTS 用于维护 hello-scholar；安装模板用于被安装项目。不是为不同模型复制两套规则。

| 内容 | 处理 |
| --- | --- |
| 全文阅读、反复思考、固定规划步骤 | 删除通用教程；保留“依据相关事实确定改动”的简短原则，读取规模由风险决定。 |
| 用户修改、外部契约、大文件、原始实验结果 | 保留，属于实际资产和项目约束。 |
| 验证 | 一条完成契约：运行相关检查，修复本次变更导致的问题；没有变化或新疑点时不重复同一检查。 |
| 完成与授权 | 明确范围内持续实施、验证与必要文档维护；“只审计/只设计”的请求停在对应结果。 |
| 提问 | 缺失事实先查；只对无法推断且会改变结果的选择提问，沿用已经给出的授权。 |
| 代码注释 | 说明不明显的契约、原因和风险；取消每个阶段都要注释的要求。 |
| 项目位置 | 安装模板说明 Spec、Record、Architecture、Handoff 的路径和生成索引归属。 |
| 开发命令 | 仅仓库 AGENTS 写 `npm test`、`npm run test:js`、`npm run test:py` 与 docs 命令；用户项目使用自身命令。 |
| 中文和输出偏好 | 合并成简短段落，保留任务语言覆盖。wrapper 是用户偏好，可保留；不强制展示内部技能名称或尾部提问。 |

建议安装模板采用如下执行语义，具体文字在实施时结合源文件落定：

> 用户要求实施时，依据当前 Spec 和项目事实完成范围内修改、相关验证及必要文档维护。计划和临时任务由 Agent 按需组织，无需生成或审批 plan.md、tasks.md。已有授权持续有效；遇到会改变产品决策的未决问题，或需要超出当前授权的操作时再询问。只要求分析、设计或审计时，交付对应结果。

## 6. 分阶段实施及验证

1. 固定质量标准、新协作契约与文档边界 -> 验证：先定义每个技能的结果指标与有无技能的对照案例，再建立 Spec-only 验收场景。不把旧测试措辞或必须出现失败的基线视为新版目标。
2. 协同替换执行与文档模型 -> 验证：修改 Skills、Spec/Record 模板、发现器、校验器和索引；只有 Spec 的项目可以 check/sync，关联 Record 不需要 Plan，Spec 缺口能被审计。此阶段内部可分提交，整体可用后才发布。
3. 精简 AGENTS 与技能分发 -> 验证：安装模板与仓库规则分离；新项目默认获得全部九个保留技能；旧 link/copy 安装、断链、重复安装和用户自定义内容均有边界测试。
4. 处理历史数据与参考文档 -> 验证：更新 README 和迁移说明；对已有文档逐项分类，保留历史决策与结果；活动材料中不存在指向已删除技能的调用，历史基线仍保留原意。
5. 做 GPT-6 对照评估并决定发布 -> 验证：相同模型、环境、场景和预算比较简短规则、新技能与旧技能；通过行为结果和安装回归后发布，不因目录数量减少就宣告收益。

### 迁移必须覆盖的具体范围

- Prompt 与模板：`AGENTS.md`、`AGENTS-zh.md`、全部受影响的中英文 SKILL、assets、references、`agents/openai.yaml`。活动引用一次替换，不保留别名调用链。
- 文档代码：`src/document-discovery.js`、`src/document-validation.js`、`src/index-generator.js` 及相关 CLI 测试。去掉默认 Plan/Tasks 缺失提示、审批列和关联门；为 Spec 的证据展示定义清楚语义。
- Record：新写入契约仅关联 `spec` 和 `spec_revision`，允许二者同时为空；保留 Run ID、时间、实际日志、退出状态和复现事实。
- 持久格式：已有 `schema: 1` 数据是真实兼容边界。推荐采用明确的新 schema 和只读旧格式支持，新写入只用新格式；先盘点目标安装的数据再决定旧读取器退出时间，不自动改写历史 Record。
- 历史 Plan/Tasks：未完成且仍有效的需求回到 Spec，执行事实归入验收证据或 Handoff，纯历史策略继续作为历史材料。没有逐项核对前不批量删除文档，不把代码尚未完成的要求丢掉。
- 安装器：`src/install.js`、`src/skill-discovery.js`、`src/fs-ops.js` 及安装测试。退休清单用于识别旧受管目标，不用来保留旧执行接口。验证链接实际指向、copy marker 和用户修改；归属不明时保留并报告。重新安装更新指令块，单靠 symlink 不会更新已复制的 AGENTS 内容。
- 测试：新行为用新场景；保留解析、路径安全、原子索引、原始证据完整性测试。旧模型轨迹与冻结协议不能被改写成 GPT-6 结果。

## 7. GPT-6 验证方案

质量判断和执行协议以 [技能质量评估方案](skill-quality-evaluation.md) 为准。以下为审计阶段提出的场景候选；最终根据任务价值安排，并保留每个技能的独立结论。

模型能力需通过当前目标环境验证。建议使用三组：A 为简短项目规则加 Spec，B 为同样规则加精简后的相关技能，C 为当前完整框架。三组使用同一 GPT-6 实际可用标识、推理设置、工具、上下文预算和同一份输入事实，记录实际模型元数据，不能只改历史结果里的模型名称。

至少覆盖以下场景，每类先做 3 次独立运行作为筛查；表现波动时再增加重复，而非把 3 次视为统计定论：

| 场景 | 可观察结果 |
| --- | --- |
| 拼写或小型内部修复 | 直接完成，不创建 Spec/Plan/Tasks，不额外索取流程批准。 |
| 完整 Spec 的功能实施 | 完成所有验收项，相关测试有效，不停在中间文档审核。 |
| Spec 有关键歧义 | 只询问真正影响行为的缺口，不把可查事实抛给用户。 |
| 跨模块重构或迁移 | 契约保留、内部旧调用清理、真实持久数据边界得到处理。 |
| 中断和新会话续做 | 从 Spec、代码和证据恢复，不因缺 tasks.md 或 tracker 而停止。 |
| 实现尚未完成时审计 | 直接报告有证据的缺口，不先要求全部任务完成。 |
| 普通测试与正式实验 | 普通测试直接跑；正式实验保留复现和终态证据，负结果不伪装为失败。 |
| 已授权的架构维护 | 从已实施事实更新相应文档，不额外索取 Hash 批准。 |
| 当前任务指定英文 | 覆盖仓库中文默认，保留必须原样的符号和模板结构。 |
| 用户要求仅规划或仅审计 | 不越界实施、启动实验或修改外部系统。 |

比较指标为验收满足率、严重回归、越权写入、必要证据缺失、不必要提问、加载的技能与参考材料量、模型 tokens、实际耗时。让评估者只看相同任务事实和结果，不要求特定标题、固定步骤或技能一定被调用。

候选版本在测试组合中不得出现未解决的用户修改丢失、伪造验证、未授权外部写入和正式实验原始证据丢失；结果质量至少不低于 A，才有理由宣称该版本有改善。没有证明稳定增益时标记证据不足，优先修订；默认安装九个技能的决定不由评估自动改变。若发现明确回归，补具体契约或参考，不恢复整条 Plan/Tasks 流水线。

正式评估会产生模型费用，应在实施阶段明确预算和停止条件，并按保留证据的实验运行；本轮未启动。
