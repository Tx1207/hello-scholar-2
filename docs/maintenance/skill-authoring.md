# Skill 维护参考

本文件保存 hello-scholar Skill 的维护判断，不参与运行时发现。

## 目标

Skill 应提供模型无法从通用能力中稳定推断、并会改变任务结果的约定。质量看真实任务中的决定、产物和证据是否改善，不看文件长度、标题数量或自评分。

## 设计检查

- description 只说明能力和有区别度的适用条件；避免同义触发词和“所有任务都使用”的路由。
- 入口保留共同目的、关键约束和分支选择；只在特定分支使用的 schema、示例或长流程放入 reference，并从入口说明何时读取。
- 一个行为只有一个事实源。删除模型默认会做的 no-op、重复规则、陈旧兼容说明和没有现实失败依据的防御分支。
- 固定步骤只用于顺序影响正确性或安全的流程。开放式设计应描述结果、判断标准和停止条件，不固定标题或访谈轮数。
- 写入、外部副作用和付费操作分别遵守用户授权；Skill 不能把完成任务的授权扩成另一类动作。
- 中英文镜像表达相同契约，但无需逐字翻译。平台专属 UI metadata 留在 `agents/`，不得写进跨平台正文。

## 验证

先运行 `skill-creator` 的 `quick_validate.py` 检查结构，再用代表性请求比较无 Skill、旧 Skill 和候选 Skill。检查是否正确触发、是否保留用户意图、是否产生目标产物与证据、是否出现额外审批或旁路写入。固定字符串断言只适合验证真实字段、路径和安全边界。
